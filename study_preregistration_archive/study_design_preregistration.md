# Study design (frozen before any experiment is run)

Title (working): Retrieval-Augmented and Tool-Using Language Model Analysis of Heterogeneous Logs on Commodity Hardware

Author: Vasu Atmakuri

## 1. Research questions and hypotheses

All comparisons are paired (same questions, same model, same decoding settings). Every hypothesis is
tested two-sided and reported whatever the outcome.

- H1. The tool-using agent answers more questions correctly than single-turn multi-type chunk retrieval.
- H2. Multi-type chunk retrieval answers more questions correctly than fixed-size chunk retrieval.
- H3. Both proposed pipelines (multi-type chunk retrieval, tool-using agent) outperform BM25 line retrieval
  and uniformly sampled long-context prompting.
- H4. Automatically generated source characterization (system prompts, important and noisy components)
  improves accuracy over generic prompts, and differs little from hand-written expert characterization.
- H5. Removing a chunk type lowers accuracy on the question category it was designed for:
  initialization chunks for factual recall, time-window chunks for temporal reasoning,
  error-burst chunks for causal questions.

Exploratory (no confirmatory claim): whether the method ranking holds for a second model family
(Llama 3.2 3B); unsupported-claim rate; evidence recall; latency and token usage.

## 2. Log sources

| Source | Format | Origin |
|---|---|---|
| Fault-injected ML inference service (7 components, 3 days, about 55,000 lines, 3 service starts, 7 injected incidents with known causal chains) | Python logging | Synthetic testbed generated by `benchmark_construction/fault_injected_inference_service_log_generator.py`, seed 20261101 |
| ZooKeeper service log (LogHub) | Log4j-style | Public, Zenodo DOI 10.5281/zenodo.1144100 |
| Linux system log (LogHub) | Syslog RFC 3164 | Public, Zenodo DOI 10.5281/zenodo.1144100 |

The testbed is synthetic and is described as such. Its value is exact causal ground truth.

## 3. Benchmark

- Four categories: factual recall, temporal reasoning, comparative, causal.
- Questions are generated from templates; gold answers are computed by independent reference readers
  (not the system's parser) or, for the testbed, from the generator's event manifest.
- Ambiguity filters: unique maxima with margins, no events at time-window boundaries, unique event ordering.
- Size: 70 testbed, 48 ZooKeeper, 50 Linux test questions (168 in total; ZooKeeper yielded 10 instead of 12
  unambiguous precedence questions); 6 development questions per source for debugging only.
- Causal questions on the public logs are temporal-precedence questions (which component logged the event
  immediately before a given event). True root-cause questions exist only on the testbed. This is stated in the paper.
- The test split is frozen by SHA-256 hashes in `benchmark_questions_frozen/benchmark_freeze_manifest.json`.
  No system component is tuned on test questions.

## 4. Methods compared

1. BM25 line retrieval (top 5 lines).
2. Long-context prompting: as many lines as fit in the context window, sampled uniformly across the file.
3. Fixed-size chunk retrieval: 1,024-character chunks, 128 overlap, same embedding model, top 8.
4. Multi-type chunk retrieval: time-window, error-burst, logger-thread, initialization chunks, top 8,
   characterization-derived system prompt.
5. Tool-using agent: search, statistics, timeline and sample tools, at most 10 model turns.

Models: Qwen3-4B-Instruct-2507 (primary) and Llama 3.2 3B Instruct, both 4-bit quantized (Q4_K_M), served
locally by Ollama. Context window 8,192 tokens, temperature 0, seed 42, at most 768 output tokens.

Model selection was settled on development questions before any test run: the hybrid Qwen3 4B model wrote its
reasoning into the answer and exhausted the output budget before answering (and did not call tools) with its
reasoning mode disabled, and produced no answer within the budget with it enabled. The non-reasoning
instruction-tuned release answered in the required format and called tools reliably. A reasoning-mode
ablation is therefore not part of this study.

Prompt budgeting: evidence is packed to an estimated budget (1.8 characters per token, measured at about 2.1
for these logs). If the runtime reports that a prompt exceeds the context window, evidence is reduced by 20%
and the call retried, up to four times. If a response lacks the 'FINAL ANSWER:' line, one follow-up turn asks
the model to state its final answer from its own response. Both events are recorded per run and reported.
Embeddings: all-MiniLM-L6-v2. Index: FAISS exact inner product. Hardware: Apple M1, 8 GB memory.

## 5. Experiments (in execution order)

1. Main comparison, Qwen3-4B-Instruct-2507, all sources, all five methods.
2. Characterization ablation: generic prompts, all sources, methods 4 and 5.
3. Characterization ablation: expert prompts (written by the author before running), all sources, methods 4 and 5.
4. Main comparison with the second model family (Llama 3.2 3B), all sources, all five methods.
5. Chunk-type ablations: each chunk type removed in turn, testbed, methods 4 and 5.

## 6. Measures

- Primary: answer correctness, graded automatically from the text after "FINAL ANSWER:" by answer type
  (integer, numeric with tolerance, entity, choice, timestamp within 60 s, hour, acceptable keywords).
- Secondary: response contains an unsupported claim (timestamp, identifier, IP, version or quoted text
  not present in the log); recall of key evidence lines; wall-clock latency; prompt and completion tokens;
  model and tool calls.
- Grader validity: an independent second rater grades all open-ended answers plus a random sample of 60
  others, blinded to method; agreement and Cohen's kappa are reported.

## 7. Analysis plan

- Accuracy with 95% Wilson intervals and 2,000-sample bootstrap intervals, per source and pooled.
- Paired exact McNemar tests between methods within each experiment, Holm correction per experiment.
- Each ablation compared with the main run on identical questions (exact McNemar, Holm correction across ablations).
- Significance level 0.05. Effect sizes (accuracy differences and discordant counts) reported alongside p-values.
- Runs that fail with a software error are retried once; remaining failures are reported as incorrect.
- Any deviation from this plan is reported in the paper with its reason.
